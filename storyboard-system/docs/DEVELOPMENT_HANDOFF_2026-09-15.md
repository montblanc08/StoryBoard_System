## 5. 优先处理的故障

### P0-A：画板保存合同不一致（已证实）

`static/creative-boards.js` 的 `newItem()` 给全部新对象添加 `z`，包括情绪板。`creative_boards.py::normalize_boards()` 的允许字段和类型附加字段不接受 `z`，可复现 `ValueError: item: invalid object or unknown fields`，接口返回 400。

`flushCreativeBoards()` 保存失败会阻止导航。因此最新浏览器测试在等待灯光图出现时超时，和该错误链路一致；仍应记录 HTTP 响应进一步验证完整因果。

接手应完成：前后端合同统一、旧数据默认值/迁移、类型约束、混合画板保存与重载、备份导入校验。不要只修改白名单而漏掉第二层 `extras/permitted` 校验。情绪板不应无意义携带灯光空间字段。后端改变后必须同步部署后端，旧静态发布脚本不足以修复。

### P0-B：首屏旧样式闪现、登录页被跳过（用户报告，尚未定位完）

检查 `static/index.html` 初始 body 为 `data-context="hub"`，并加载多层旧新 CSS；React 外壳初始化后才设置 UI 状态。调查认证未决阶段是否已显示内页、脚本失败是否露出旧壳、缓存版本是否混用。

入口线索：`static/app.js` 中 `/api/session` 初始化约在 1692 行；`src/workspace/index.tsx` 的 UI mount；HTML 初始可见性。必须分别测试无 Cookie、有效会话、失效会话、接口缓慢/失败、退出后刷新。有效会话自动进入可能是原有行为，不能未经证据把它认定为鉴权绕过或强制所有刷新重新登录。未认证时不可显示受保护数据。
